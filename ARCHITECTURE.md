# LifeLine architecture

The original architecture is retained: React/Vite + shadcn/Tailwind → FastAPI → validated model inputs → baseline/heuristic/MILP → independent physical checks → typed results and deterministic explanations.

## Data paths

1. Synthetic mode: fixed daylight curve × preset/user cloud factors → 24 PV-energy values.
2. Historical mode: bundled NASA POWER hourly irradiation → shared PV conversion → 24 PV-energy values.
3. Live mode: fixed-host Open-Meteo adapter → validated, timestamped forecast/cache → IANA-local interval integration → shared PV conversion → 24 PV-energy values. Non-24-hour local days are rejected for simulation.

All three methods within a comparison receive the exact same immutable `ModelInput`. In live sensitivity runs, each explicitly labeled sunlight multiplier produces a new comparison with the same equipment, physical limits and midnight charge. No weather is generated by a language model.

## Modules

| Module | Responsibility |
|---|---|
| `backend/app/weather_forecast.py` | Fixed upstream URL, timeout, cache, validation, interval alignment, nighttime rules |
| `backend/app/forecast_models.py` | Strict public forecast/plan/tool contracts |
| `backend/app/forecast_planner.py` | Adapt forecasts to existing inputs, serialize calculations, generate computed assessments |
| `backend/app/planner_tools.py` | Read-only configuration/forecast and validated simulation dispatch; constrained non-LLM fallback |
| `backend/app/forecast_routes.py` | Additive HTTP endpoints |
| `backend/app/solar_forecast.py` | Existing synthetic generator plus shared irradiation-to-PV conversion |
| `backend/app/energy_simulator.py`, `optimizer.py`, `heuristic.py` | Existing dispatch, optimization and comparator; unchanged |
| `frontend/src/components/LiveForecastPlanner.tsx` | Location, provenance, explicit midnight assumption, computed schedules, uncertainty and errors |

Forecast calls run asynchronously; the existing solve lock and worker thread serialize MILP work without blocking health/catalog requests. Forecast service clocks/transports are injected for offline unit/integration tests. The local cache is bounded and does not constitute durable storage or a distributed deployment cache.

## Assistant boundary

The hosted LLM is not configured in this release. Tool JSON Schemas and a validated execution boundary are available for a provider integration. The working guided planner is explicitly deterministic. Model-generated arguments cannot edit essential requirements, supply weather values, change numerical results or control equipment. Unknown guided requests require clarification.

Future hosted integration requires an explicit provider credential decision, environment-only secrets, bounded tool calls, and tests of real provider behavior. A tool-interface test is not proof that an LLM has run. A local/remote LLM outage must preserve the ordinary deterministic planner and clearly disclose the unavailable provider.
